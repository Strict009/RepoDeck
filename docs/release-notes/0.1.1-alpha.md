A stabilisation release. No new features worth the name — this is about RepoDeck behaving
sensibly on machines it was not built on, and being able to tell you what went wrong when it
does not.

It is still an alpha. It is an alpha that has now been installed, used, updated, repaired,
emptied and uninstalled on a physical machine that is not the one it was compiled on, which
0.1.0-alpha could not say.

## If RepoDeck does not start, it now says so

Previously it simply vanished. The log is written by a component that starts after the
window does, so any failure before that point produced no window, no message and no file —
just a shortcut that appeared to do nothing, forever.

RepoDeck now writes a crash report to `%LOCALAPPDATA%\RepoDeck\Logs\` and shows a message
box naming the file. For the failures a fresh machine actually produces — a missing library,
a build for the wrong kind of processor, a folder it was refused access to, a full disk — it
says what that probably means in words. For anything it does not recognise it says nothing
rather than guessing, because a confident wrong explanation sends you off to fix the wrong
thing.

## Reporting a problem got easier

**Settings → Reporting a problem → Copy diagnostic report.**

Copies your version, this computer's details, where RepoDeck keeps its files, whether it can
actually write there, and how the GitHub allowance looks. Paste it into an issue.

It contains no tokens, no credentials, no file contents, no search history, and no list of
what you have installed — only how many. Paths inside your profile are shown as
%LOCALAPPDATA% rather than spelled out, so the report says which folder is in use without
naming you.

## RepoDeck can tell you when there is a newer RepoDeck

**Settings → RepoDeck itself → Check for update.**

It checks, shows what changed, and offers to open the release page. It does **not** update
itself, and that is deliberate rather than unfinished: RepoDeck updates other programs by
moving the old copy aside and swapping a checked new one in, and a running program cannot
have its own files moved out from under it. Building a second mechanism to do that safely is
real work, and a half-built one would mean the part responsible for recovering from bad
updates is itself the thing that breaks.

## Tested on real machines

**0.1.0-alpha** was installed from this project's release page onto a different physical
Windows PC and used there: it downloaded, warned about being unsigned as expected,
installed, started, searched GitHub, found a project and installed it. That answered the
question the previous release could not answer about itself — **RepoDeck starts and works on
a computer that is not the one it was built on**, with no .NET or anything else installed
first.

What it did not answer was everything that comes after installing something. **0.1.1-alpha**
has now been through that half, on the second PC and on the machine RepoDeck is built on:

| Step | Result |
|---|---|
| Launch an installed application from RepoDeck | Pass — it ran |
| Still recognised after RepoDeck restarts | Pass, including "Last run just now" |
| Upgrading 0.1.0-alpha to 0.1.1-alpha over the top | Pass |
| Windows registration after the upgrade | Pass — one Start Menu entry, one entry in Apps & features, no administrator prompt, nothing unusual asked |
| Version reporting | Pass — Settings shows 0.1.1-alpha |
| RepoDeck's own update check | Pass — reports itself current, does not offer the older public release, does not get prerelease ordering wrong |
| Repair | Pass — an executable was deleted on purpose; RepoDeck said "Program missing, 2 things are wrong" and put it back |
| Repair leaving your data alone | Pass — the application's own settings and `user/` folder kept their original timestamps |
| Removing an application | Pass — only the folder RepoDeck owns was deleted |
| Staying removed | Pass — searching for it again showed no installed marker |
| Diagnostic report privacy | Pass — checked by searching the copied text for the Windows user name, token patterns, installed application names and full profile paths. None present |
| Uninstalling RepoDeck through Windows | Pass — program files, Start Menu entry and the Apps & features entry all removed |
| Your data after uninstalling | `%LOCALAPPDATA%\RepoDeck` left completely untouched |

Three of the things listed under **Fixed** below were found this way rather than by reading
the code.

Both machines belong to this project. Nobody else has run it yet.

## Fixed since 0.1.0-alpha

- **An installed application could be offered an update it could never download.** A release
  asset with no download address was treated as installable. RepoDeck now ignores assets it
  has nowhere to fetch from.
- **A damaged settings file could hand out empty records** rather than being ignored. A file
  containing `[null,null]` is valid JSON and parsed happily into a list of nothings, which
  would then break whatever touched it. Four files were affected: your installed list,
  favourites, activity history and recently viewed.
- **Startup cleanup could in principle delete an installed application.** RepoDeck sweeps
  leftovers from an interrupted update by matching folder names, and the pattern would also
  have matched a real application whose project name happened to contain the same text. It
  now requires the exact shape it creates, and refuses to remove any folder an installed
  application claims.
- **Leftovers from an interrupted update were sometimes never cleaned**, because the sweep
  gave up early when a related folder was already gone.
- **RepoDeck could offer itself a pre-release when running a finished version.** It now
  applies to itself the same rule it applies to everything else.
- **The diagnostic report contained your Windows user name** inside every path. Paths under
  your profile are now shown as %LOCALAPPDATA% and similar, which says which location is in
  use without naming you.
- **The count at the bottom of the window never changed.** It was worked out once, when
  RepoDeck started, and then left alone — so installing something or removing something left
  the strip still reporting whatever had been true when you opened the window. Removing your
  only application left it insisting you still had one.
- **Uninstalling RepoDeck asked the wrong question.** Windows asked whether to "completely
  remove RepoDeck and all of its components" — and then left behind everything RepoDeck had
  installed for you, which on a used machine is most of what is on disk. Leaving it is
  deliberate: uninstalling RepoDeck must not uninstall the programs you used it to install.
  Not saying so was not. The question now describes what it does, and the uninstaller ends by
  naming the folder it kept and why. It does not offer to delete it as well; a prompt that can
  wipe everything you installed does not belong at the end of a wizard.
- **The welcome screen occupied the top third of the window** and left the rest empty, which
  read as a page that had failed to load rather than as breathing room.

## Unchanged

RepoDeck still will not run installers, scripts or anything else it downloads, will not ask
for administrator access, and will not touch anything outside its own folders.

It still cannot tell you whether software is safe or trustworthy, and nothing it shows you is
a recommendation.
