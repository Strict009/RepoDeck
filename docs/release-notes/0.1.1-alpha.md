A stabilisation release. No new features worth the name — this is about RepoDeck behaving
sensibly on machines it was not built on, and being able to tell you what went wrong when it
does not.

**This release is not finished.** It is waiting on a clean-machine test run. Anything that
run turns up belongs here before this is published.

## If RepoDeck does not start, it now says so

Previously it simply vanished. The log is written by a component that starts after the
window does, so any failure before that point produced no window, no message and no file —
just a shortcut that appeared to do nothing, forever.

RepoDeck now writes a crash report to `%LOCALAPPDATA%\RepoDeck\Logs\` and shows a message
box naming the file. For the failures a fresh machine actually produces — a missing library,
a build for the wrong kind of processor, a folder it was refused access to, a full disk — it
says what that probably means in words. For anything it does not recognise it says nothing
rather than guessing, because a confident wrong explanation sends you off to fix the wrong
thing.

## Reporting a problem got easier

**Settings → Reporting a problem → Copy diagnostic report.**

Copies your version, this computer's details, where RepoDeck keeps its files, whether it can
actually write there, and how the GitHub allowance looks. Paste it into an issue.

It contains no tokens, no credentials, no file contents, no search history, and no list of
what you have installed — only how many. It does contain paths, which include your Windows
user name, and it says so rather than pretending otherwise.

## RepoDeck can tell you when there is a newer RepoDeck

**Settings → RepoDeck itself → Check for update.**

It checks, shows what changed, and offers to open the release page. It does **not** update
itself, and that is deliberate rather than unfinished: RepoDeck updates other programs by
moving the old copy aside and swapping a checked new one in, and a running program cannot
have its own files moved out from under it. Building a second mechanism to do that safely is
real work, and a half-built one would mean the part responsible for recovering from bad
updates is itself the thing that breaks.

## Fixed

- **An installed application could be offered an update it could never download.** A release
  asset with no download address was treated as installable. RepoDeck now ignores assets it
  has nowhere to fetch from.
- **A damaged settings file could hand out empty records** rather than being ignored. A file
  containing `[null,null]` is valid JSON and parsed happily into a list of nothings, which
  would then break whatever touched it. Four files were affected: your installed list,
  favourites, activity history and recently viewed.
- **The welcome screen occupied the top third of the window** and left the rest empty, which
  read as a page that had failed to load rather than as breathing room.

## Unchanged

RepoDeck still will not run installers, scripts or anything else it downloads, will not ask
for administrator access, and will not touch anything outside its own folders.

It still cannot tell you whether software is safe or trustworthy, and nothing it shows you is
a recommendation.
